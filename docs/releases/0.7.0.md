# Karaoke Platform 0.7.0

This release consolidates the recent playback, ingestion, search, vector, and operations work.

## Playback and queueing

- Added a systemd user-managed Chrome kiosk service with CDP on port 9222.
- Added a systemd-managed Web TUI service on port 8001 for easy reloads.
- Moved kiosk restart control to the Admin TUI (`K`).
- Added Admin TUI live recording controls, recording status, recent recording list, and Enter-to-process behavior.
- Added Web TUI progress reporting for local folder scans and persistent scan logging.
- Made `Follow Karaoke Queue` (`o`) authoritative whenever a local queue is active, preventing YouTube Music's temporary queue from silently taking over.
- Added header controls for previous, play/pause, next, Audio/Video, shuffle, and repeat.
- Moved blocking song navigation off the TUI event loop so slow CDP calls do not swallow subsequent keypresses.
- Added automatic CDP handling for common English and Dutch playback/content dialogs.
- Added responsive duet cartwheel visuals with mirrored dancers, mood/genre interaction, bass/brightness-driven motion, meeting phases, and narrow-panel safety.

## Search and browsing

- Added a 70-item random startup wildcard queue with no autoplay.
- Added shared sort handling for library and queue views, defaulting to Mood/Energy.
- Added sort selection to Browse mode and synchronized sort selectors.
- Added fuzzy token matching for typos and multi-word queries.
- Capped initial library rendering to avoid loading the full collection into the TUI at startup.

## Ingestion and vectors

- Added detailed folder-scan progress callbacks and per-file logging.
- Added unattended collection scan tooling for local music archives.
- Added `ytmusicapi` integration for authenticated YouTube Music playlist listing, import, and synchronization.
- Added automatic extraction of YouTube Music authentication headers from the running kiosk Chrome profile when CDP is available.
- Updated vector and search documentation with current index coverage and production index names.
- Added recurring vector refresh support every 40 minutes with lock-aware failure reporting.
- Added SQLite busy-timeout handling so ingestion and the Web TUI can overlap without immediate database-lock crashes.

## Verification

- Full test suite: 1,566 tests passing.
- Web TUI service verified responding on `http://127.0.0.1:8001/`.
- Kiosk service verified active with CDP available on port 9222.
